# Driving quality SDK

**Status:** in-progress

## Summary

Plug-and-play library that records GPS and IMU, detects harsh acceleration, braking, and cornering, and exposes live metrics plus a full local session. **Expo/RN** hosts use `@harshy/sdk`. **Native Android/iOS** hosts use `HarshyClient` (Kotlin/Swift) in `@harshy/native` — same session schema, no React Native.

## Behavior

- `createHarshy()` is the **JS** host API: start/stop a trip, subscribe to live GPS/IMU plus `onMetrics` / `onEvent`, pin `detector` / `native` on the client or per `start()`, and get `SessionExport` on stop. `getDetectorConfig()` returns the merged config. `stop()` always re-runs `analyzeTrip` on the recorded samples. Pass `historyStore` to persist compact sessions across reloads (`loadHistory`). Headless hosts with their own GPS/IMU call `analyzeTrip` from `@harshy/sdk` — do not copy detector math into the host. Native Android/iOS apps use `HarshyClient` instead (`packages/native/README.md`, [native-sdk.md](native-sdk.md)). Do not run `HarshyClient` and the Expo module in one process. See [`packages/sdk/README.md`](../../packages/sdk/README.md).
- `requestPermissions()` resolves after the OS prompt (not immediately). It returns `location`, `backgroundLocation`, `motion`, and `notifications`, and asks only for foreground location, motion, and notifications. `requestPermission(kind)` asks for one of those, or background location. Background location is also `requestBackgroundLocation()`. The host explains that permission in the app before either call. Hosts must not start native capture until `location` is `"granted"`. GPS/IMU for a trip start only in `start()` and stop in `stop()`. Hosts may call `startPreview` for a foreground readout that is not a trip.
- Background: iOS Always + `location` background mode; Android foreground service while the trip runs. `background: true` is the native default. On Android the in-progress track is written to disk and the sticky location FGS restores capture if the system kills the process; JS `recover()` / native `HarshyClient.recover()` attach to that live trip and keep journaled `trigger` (`auto` vs `manual`; older journals without it are `manual`). `recover()` does not re-fire journal GPS on `onLocation`; `getLiveLocation()` returns the in-memory track while a trip is running.
- `source: "native" | "simulated" | "auto"`. Auto uses native on iOS/Android and the simulator elsewhere.
- Detector config is tunable live; `retune()` re-runs `analyzeTrip` on the last samples.
- GPS fixes that imply an impossible step (teleport / out-of-band jump) are **rejected in `pushLocation`** — they never enter session `location[]`, trip distance, or kinematic events. A step where both the track and the reported speed change faster than 12 m/s² is held for one fix. It is kept when the next sample still reports at least 60% of that speed, or the track keeps moving away from the previous point. A snap back to the previous speed and place is dropped, so a one-sample glitch cannot become `maxSpeedMps`. A real run that stays at that speed is kept, including a sustained 119 km/h. An unconfirmed hold is dropped on `finalize`. Already saved recordings keep their stored max speed. Coarse network-like injects (null speed, ≤7 lat/lon fractional digits, **and** accuracy worse than 50 m or missing) are also rejected and do not count toward segment reset. GNSS-quality fixes that omit speed (typical first GPS samples) are kept; speed is filled from displacement when the OS leaves `speedMps` null. Fixes that omit bearing fill `courseDeg` from the path heading. GPS long/lat accel (live G-force) uses a 0.2–8 s window so sparse fused samples still count. Native Kotlin/Swift analyzers stay in parity. After enough consecutive speed-gate rejects the next fix is accepted as a new segment (coverage gap). Android capture **registers GPS + platform fused (API 31+, high-accuracy `LocationRequest`) + network**; fused is not skipped when `getAllProviders` / `isProviderEnabled` omit it. Analyzer still prefers GPS and uses fused/network only when GPS is off, still searching, or silent >8 s. Each provider gets a new listener on every start (`LocationFeeds`); trip registration runs on the main thread and rebinds once if no sample arrives. Searching GPS is journaled until a usable lock exists, then dropped while that lock is fresh when fused is registered; last-known older than 30 s is not seeded. No Play Services fused client. iOS `CLLocationManager` is already fused. iOS Expo `onLocation` sends `NSNull` for missing fields so JS Zod parse does not drop the sample.
- Trip score is a relative **0–100** grade: `clamp(100 + points × lengthWeight, 0, 100)`. Length weight is `refKm / km` (floored at `minDistanceKm`), clamped **0.5–2.5**, so the same negative points hurt more on a short trip. Absolute **points** are the sum of fixed event amounts (can go negative; capped at 100). Time and severity do not scale an event. Kilometres **1–10** that finish with no harsh accel, brake, corner, swerve, or jerk pay **+2** (`smooth_km`). Each later clean kilometre pays **+1**. A gentle accel, brake, or corner pays **+2**. Harsh light / medium / heavy: accel **−5 / −8 / −12**, brake **−8 / −12 / −16**, corner **−4 / −8 / −12**, swerve **−4 / −7 / −10**, jerk **−3 / −5 / −6**. Speeding, possible impact, and phone in hand are **0**. Overlap tags add nothing. A gentle credit still needs 0.5 m/s² up to 0.6× that axis's harsh threshold, held 3 s and 15 m, then that type waits 400 m. A very gradual accel or brake from 0.2 m/s² up to that 0.5 floor pays **+1** after 8 s, 40 m, and at least 2 m/s of speed change. From 0.6× harsh up to the harsh line there are no points. A gentle corner also needs the same-sign lateral hold and at least **15°** of net track heading change (GPS path wiggles on a straight road do not credit). Already saved recordings keep their stored score until retune.
- Harsh accel, brake, and corner use four bands vs the type threshold: **within norm** (below), **light** (at the threshold), **medium** (1.5×), **heavy** (2×). Events are never `norm`. Live metrics expose `accelLevel` / `brakeLevel` / `cornerLevel` / `swerveLevel`. Scoring still uses continuous `severity` (0–1). During cooldown, a higher band of the same type upgrades the existing event (`onEvent` may fire again with the same `id`).
- Speeding is optional (`speedingMps`). When set, it is one span per excursion above the cap (`endT` when speed drops below 95% of the cap). **Corner and swerve** use the track heading when both steps are at least 2 m. If the chip course disagrees with that track by more than 45°, it counts only when a mounted phone’s gyro about gravity is between 0.5× and 2.5× that chip yaw. A handheld phone, a quiet gyro, or no gyro falls back to the track, so a straight road is not a corner. Gyro never creates an event by itself. Chip↔path agreement alone does **not** clear path-only gates — fused GPS bearing often echoes the polyline, so a mounted gyro about gravity must confirm the yaw. **Path-only** lateral (no gyro confirm) is capped: fixes poorer than **15 m** accuracy or laterals above **6 m/s²** are ignored, and a harsh corner still needs the same-sign band held **1 s / 8 m** with at least **20°** of net track heading change so a GPS zig-zag at trip start is not scored. A swerve emits only when every sample in the elevated yaw spike was gyro-confirmed; a path-only spike is dropped. Chip/gyro-confirmed corners emit immediately. Stored `courseDeg` stays the OS chip value (null when omitted); displacement fill is only for the live `headingDeg` filter. Both window samples must be at or above `minSpeedMps` for yaw; a swerve also needs speed ≥ `swerveMinSpeedMps`, a sharp yaw rise (`harshSwerveJerkRadps2`), and yaw falling again within `swerveMaxElevatedMs` (default 2 s) so steady low-speed turns are not swerves. A same-sample harsh corner wins. Twisting a phone in the hand, or a heading jump while stopped, is not a swerve. Already saved recordings are not rewritten. Live **heading** (`headingDeg`) is a display filter: blank until speed is at least `minSpeedMps` and two GPS courses agree, circular EMA while moving, last value held when stopped. Missing GNSS bearing is filled from displacement before that filter. Same-type peaks inside `cooldownMs` (default **3.5 s**) upgrade one event instead of stacking. Accel, brake, corner, swerve, and speeding that fall inside `compoundWindowMs` tag `overlaps` and add `score.compound`. IMU **jerk** is a GPS-weak fallback; it is ignored for `jerkSettleMs` (1.5 s) after trip start so Start haptics and handling the phone are not scored.
- **Road quality** is a path measure on `location.roadRmsMps2` (1 s world-up linear-accel RMS, gravity-projected). Native engines stamp it when GPS is captured; JS finalize keeps stamped values when IMU is omitted from Expo stop. It is **not** an event and does **not** change the trip score. See [road-quality.md](road-quality.md).
- **Possible impact** (`possible_impact`) is a short IMU pulse plus a GPS speed change (or a very large peak). Hosts match it with `isPossibleImpact` and label the axis with `impactDirectionLabel`. It is **not** a confirmed crash, **not** emergency calling, and **not** a score penalty (`eventWeight` 0, not compound). Direction is `front` / `rear` / `rollover` / `unknown` only. See [possible-impact.md](possible-impact.md).
- **Phone handheld** (`phone_handheld`) is a span while GPS speed ≥ `minSpeedMps`: gravity tilt from a quiet mount baseline plus handling motion. Hosts match it with `isPhoneHandheld`. It is **not** a score penalty (`eventWeight` 0, not compound). See [phone-handheld.md](phone-handheld.md).
- `createHarshy({ liveDisplayTitle })` sets the Android trip notification / iOS Live Activity title. The default is **Apexmatic**. Hosts should pass their own app name.
- `setUploadAdapter()` is optional. Nothing is uploaded until a host provides an adapter.
- **Automatic trips**: default remains manual. `arm()` / `disarm()` / `getWatchState()` opt into a sparse **watch** that is not a trip. Auto reuses `start` / `stop` / `recover` and sets session `trigger`. Auto start is a short **warmup** (probe 5 s / 40 m); commit is 20 s / 150 m on trip GPS, then auto-end is 10 min parked (`endHoldMs`), including when GPS was silent for that long and resumes already slow; that dwell (or dead journal hole) is cut from the saved session. A failed warmup aborts after 30 s parked and is discarded. Native MotionWatch feeds `WatchFix` samples. See [auto-trip.md](auto-trip.md).
